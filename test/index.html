Context

課題

社内の文書は、すべて独自形式で管理・蓄積されていた。専用ソフトがなければ開けず、公式サポートは終了し、機能のカスタマイズもできない。顧客への納品時には、毎回PDFへ変換する必要があった。

社内にはすでに Google Workspace の Gemini が導入済みであり、現場でも自発的にAIを使った効率化が始まっていた。とはいえ書類は独自形式のままで、AIにそのまま渡せるものは限られていた。

このシステムを使う社員は全国で634名おり、ITリテラシーにも差がある。ヒアリングで見えたのは、元データと変換後データの二重管理が人によってばらばらなこと、そして操作感が変わると使われなくなること、の2つだった。

着手前：独自形式のままではAIに渡せない
DESIGN 設計
Point01

作らない選択肢から先に検討した

最初に検討したのはRPAだった。画面操作を自動化できれば開発せずに済む。ただ設定にITリテラシーが要り、全国634名には配れない。処理も遅く、クラウド型ではデータが社外に出る。操作性・処理速度・セキュリティで比較し、DocuWorksの公式APIを使う専用ツールを選んだ。開発に使うAIも自分で検証してClaudeを採用している。

Point02

着手の順番は、代替手段が無い側から

工程の順番でいえば、着手すべきは変換ツールであった。しかし代表に必要性を示すには、代替の効かないものから作る必要がある（変換は「できない」のではなく「非効率」の問題）。一方、PDFにした後の編集・階層管理・押印には手段そのものが無かった。プレゼンのしやすさも踏まえ、手段の無い側——編集ツール（pdf-annotator）から着手した。

Point03

使用期間の違うものを、同じ中に入れない

すべてを1本にまとめると操作が複雑になり、工程によっては使わない機能も出てくる。加えて変換ツールは、社内のPDF移行が完了すれば役目を終える一時的な機能である。長期的に使う編集ツールと同じシステムに入れると、不要になった機能を抱えたまま運用し続けることになる。そのため使用期間の異なるものを切り離し、3本のツールに分けた。

Point04

新しい操作を覚えさせない

現場調査で分かった一番の障害は、機能の不足ではなく「従来の操作を変えること」だった。UXを同じ操作手順にそろえ、メールでファイルを送る際に重すぎる問題もあったため、dpi は「印刷用・画面用・メール用」と用途の言葉に置き換えた。使い慣れた操作の上に載せ、目新しさは加えていない。

Tool01

形式をAI対応に

変換ツール（DocuWorks → PDF 一括変換）
Python / Flask / xdwlib / PyInstaller

ドロップするだけで変換し、サブフォルダも自動で検出する。処理はPC内で完結するためデータは外に出ず、専用ソフトなしで開ける状態になった。

工夫：変換処理は自前で実装せず、DocuWorksの公式APIを使っている。既存のエンジンを通すため動作が安定し、開発期間も短縮できた。DocuWorksが入っていないPCでは動かないが、移行期の一時的なツールという位置づけのため、この制約は許容している。

Tool02

PDFで管理する

編集ツール（pdf-annotator）
pdf.js / fabric.js / jsPDF（フレームワーク不使用）

複数のPDFをまたぐ階層グループ化を、Acrobat互換のしおりとして書き出す。日本式の電子押印やドラッグ&ドロップでの結合にも対応し、書類の管理がPDF上で完結する。

工夫：変換ツールからワンクリックでつながるようにし、工程をまたいでも操作に迷わない導線にしている。長期的に使い続ける側なので、フレームワークに依存しない構成を選んだ。

Tool03

解析にかける

保険証券解析ツール　※検証待ち
React / Claude API / SheetJS

PDFで管理されるようになった書類を分析できるようにした。書式がばらばらでも項目構造（JSON）で抽出し、Excelへの転記まで実装している。専属の担当を置かずに、加入状況や返戻率をその場で確認できる状態まで作っている。現在は担当部門の検証待ちで、運用はまだ始まっていない。

工夫：書式ごとのテンプレートを持たず、項目構造で抽出している。保険会社や様式が増えても、ツール側を作り直さずに済む。

Result

長年慣れ親しんだ操作感を損なうことなくコストを削減

3本のツールを通したことで、書類はAIが分析できる状態になった。Geminiにそのまま読ませ、転記ミスの確認や複数年度の比較ができる。目視だけだった工程が二重確認になり、人為的なミスを減らせた。

編集ツールは年間約1,200万円のコスト削減を試算している（Adobe Acrobat Standard 約1,580円/人/月 × 634名）。変換は1件約20秒の手作業が約5秒になった。操作感を現行ツールに合わせたため、社内教育もほぼ不要。依頼を待たずに作り始めたものが、会社の要件になっている。

変換したPDFを編集ツールへ自動で引き渡す経路は、あえて設けていない。DocuWorksはローカルサーバーや各自の端末にあることが多く、セキュリティの観点からファイルを自動で動かす構成を避けた。変換ツール自体も、PDFが定着すれば提供を終える前提で作っている。
